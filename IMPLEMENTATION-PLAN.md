# RielArt Website Improvement Plan

## Objective

Strengthen RielArt's production website as a clear digital studio connecting brand strategy, websites, and practical AI systems for businesses internationally. Preserve the existing static architecture, visual identity, integrations, pricing, legal routes, and approved people while improving service depth, conversion paths, accessibility, and maintainability.

## Verified baseline

- Static HTML, shared CSS, and dependency-free JavaScript
- 24 existing HTML files, nine published insight articles, and 11 local image assets
- Light and dark themes with saved preference
- Responsive navigation, FAQ accordion, blog search/filtering, form state, reveal behavior, current year, and active navigation
- Formspree inquiry handling and existing thank-you route
- Six Stripe Payment Links and current USD pricing
- Existing Client Portal, Calendly, LinkedIn, and email destinations
- Existing sitemap, robots file, redirects, legal pages, 404 page, and GitHub Pages domain file

## Implementation

1. **Shared system**
   - Consolidate design tokens and component styles into one organized stylesheet.
   - Keep the navy, blue, white, glass, system-font, and connected-system identity.
   - Retain existing class compatibility for articles, legal pages, redirects, and utility layouts.
   - Improve focus visibility, control sizing, responsive behavior, reduced motion, print styles, and no-JavaScript fallbacks.
   - Refine the dependency-free script for synchronized theme labels, accessible mobile navigation, single-open FAQ behavior, blog filtering, form state, active navigation, and restrained visual effects.

2. **Homepage**
   - Rebuild the page in the requested 15-section order.
   - Use an original CSS connected-system visual rather than third-party imagery.
   - Add capability, problem, delivery-standard, process, solution-model, fit, engagement, insights, FAQ, and contact sections.
   - Keep the free email audit prominent while retaining project inquiry, consultation, direct email, LinkedIn, and Client Portal paths.

3. **Services**
   - Rebuild the Services gateway around five connected categories.
   - Add detail pages for Brand Strategy & Identity, Web Design & Development, AI Automation & Operations, Digital Growth & Ongoing Management, and Audits & Advisory.
   - Give every detail page outcome-led copy, capabilities, scoped deliverables, process, standards, fit guidance, related models, related insights, FAQ, and conversion paths.

4. **Core interior pages**
   - Rework Work around clearly labelled representative solution models.
   - Expand Process to Assess, Define, Build, Validate, and Launch & Improve.
   - Expand About around the studio approach, approved people, principles, standards, international work, and business mailing address.
   - Reorganize Pricing without changing prices, package scope, payment links, subscription terms, advertising-spend wording, cancellation language, or currency.
   - Keep the same audit-led contact experience on the homepage and Contact page, with project inquiry and free email audit paths in one accessible form.
   - Improve the Insights hierarchy and six requested filter categories without changing article content.
   - Add a grouped FAQ page using only claims supported by the repository.

5. **Sitewide content and discovery**
   - Update navigation and footer links consistently.
   - Add unique metadata, canonicals, breadcrumbs, internal links, and accurate structured data to every new or changed page.
   - Add the new routes to the sitemap.
   - Keep internal links in the same tab and secure intended external links with safe new-tab attributes.

6. **Validation and handoff**
   - Add a standard-library static audit covering local links, headings, metadata, IDs, image alternatives, sitemap coverage, preserved integrations, safe external links, placeholder language, and development-only addresses.
   - Run the static audit and save its result.
   - Test required representative routes, both themes, interactions, and widths from 320px through 1920px.
   - Record files, routes, preserved integrations, assumptions, owner-confirmation items, and future proof slots in the changelog and final QA report.

## Guardrails

- No fabricated proof, clients, testimonials, results, awards, partnerships, offices, people, dates, or scale claims
- No external font, framework, CMS, bundler, runtime dependency, stock imagery, or autoplay video
- No changes to the approved URLs, prices, package terms, legal routes, or static deployment model
- Supplied reference media remains research-only and will not be copied into production
- No deployment or push; the owner will review and publish through GitHub Desktop
